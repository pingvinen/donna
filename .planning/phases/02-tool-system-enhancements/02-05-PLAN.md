  <files>workflows/add-tool.md, workflows/run-tools.md, workflows/begin-the-day.md, workflows/relearn-tools.md, workflows/adjust-tool.md</files>
  <action>
In each of the 5 workflow files, find the `backfill-tool-type` handler inside the `check-pending-migrations` step. The current logic is:

```
For each tool section (starting with `## <tool_name>`), check if a `- type:` line exists between `- command:` and `- version:`. If the `- type:` line is missing, insert `- type: cli` immediately after the `- command:` line.
```

Replace with heuristic type detection. The new logic for each tool section missing a `- type:` line:

1. Check if the tool section contains a `- command:` line where the value starts with `mcp:` (e.g., `- command: mcp:linear`). If so, insert `- type: mcp` immediately after the `- command:` line.
2. Else, check if the tool section contains a `- base_url:` line. If so:
   - If the capabilities section contains entries that look like GraphQL queries (contain `query {` or `mutation {`), insert `- type: graphql`.
   - Otherwise, insert `- type: rest`.
   - Insert the type line immediately after `## <tool_name>` (since REST/GraphQL tools have no `- command:` line — their format starts with `- type:`, `- base_url:`, etc.).
3. Else (no mcp: prefix, no base_url field), insert `- type: cli` immediately after the `- command:` line (the existing default behavior).

Update the commit message from `"donna(migrate): backfill type: cli on existing tools"` to `"donna(migrate): backfill tool types on existing tools"` (since it no longer only inserts cli).

The handler text must be identical across all 5 files. Read each file, make the replacement, write it back.

Note: In adjust-tool.md, the backfill-tool-type handler is at line 64 (slightly different position than the others at line 57-61). Make sure to find the correct location in each file.

<task type="auto">
  <name>Task 2: Simplify add-tool URL entry prompt to avoid Claude Code picker rendering</name>
  <files>workflows/add-tool.md</files>
  <action>
In `workflows/add-tool.md`, find the `ask-tool-type` step, specifically the section for `rest` or `graphql` type where it asks for the base URL. The current prompt is:

```
Base URL for <tool_name>? (e.g., https://api.github.com)
```

The inline `(e.g., ...)` causes Claude Code's AskUserQuestion to render the example as a selectable picker option instead of allowing free text entry.

Replace the AskUserQuestion prompt with a plain question:

```
What is the base URL for <tool_name>?
```

Move the example into a workflow prose comment visible only to Claude (not in the AskUserQuestion text). Add a line before the AskUserQuestion block:

```
The base URL is the root API endpoint (for example, https://api.github.com for GitHub REST or https://api.linear.app/graphql for Linear). Guide the user if they seem unsure, but do not include examples in the AskUserQuestion prompt text — inline examples render as picker options in Claude Code.
```

Also check the `auth-test` step where it asks for auth header name:
```
Auth header for <tool_name>? (e.g., Authorization, X-API-Key) Default: Authorization
```

Replace with:
```
What auth header does <tool_name> use? Default: Authorization
```

And move the examples into prose before the AskUserQuestion: `Common auth headers include Authorization (for Bearer tokens) and X-API-Key. Do not include examples in the prompt text.`

Similarly for the secret key name prompt:
```
Secret key name in secrets.md for <tool_name>? (e.g., GITHUB_TOKEN, SLACK_TOKEN)
```

Replace with:
```
What should the secret key be called in secrets.md for <tool_name>?
```

And add prose: `The key name should match the service convention (e.g., GITHUB_TOKEN, SLACK_TOKEN, LINEAR_API_KEY). Guide the user if needed but keep examples out of the prompt.`
