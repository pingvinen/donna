<task type="auto">
  <name>Task 1: Move capability examples out of AskUserQuestion prompts</name>
  <files>workflows/add-tool.md</files>
  <action>
In workflows/add-tool.md, the learn-capabilities step (around lines 305-345) has three AskUserQuestion blocks for rest, graphql, and mcp tool types. Each embeds an "Examples:" section with hyphenated bullet lines inside the AskUserQuestion text. Claude Code parses these bullets as picker menu options, breaking free-text input.

For each of the three blocks (rest ~lines 307-317, graphql ~lines 321-330, mcp ~lines 334-344):

1. Move the "Examples:" content and the "Format:" line ABOVE the AskUserQuestion call, presenting them as regular printed output (plain text the workflow displays before asking).
2. Keep the AskUserQuestion prompt clean — just the question asking for capabilities, with no bullets, no "Examples:", no hyphens.

The pattern should match what was already done for the URL prompt (line 130-135): guidance printed as prose, AskUserQuestion is a clean single question.

Resulting structure for each type block:

```
Print to user:
  Format: <name>: <format description>
  Example: <single example without bullet>

Use AskUserQuestion:
  Enter capabilities for <tool_name> (one per line, blank line when done):
```

Do NOT use hyphenated bullet lines (`- item`) in ANY AskUserQuestion prompt text. Avoid "Examples:" as a heading inside the prompt. Present examples as plain sentences before the prompt.

Run `npm run lint:fix` after changes.

<task type="auto">
  <name>Task 2: Make GraphQL introspection auth-optional in relearn-tools</name>
  <files>workflows/relearn-tools.md</files>
  <action>
In workflows/relearn-tools.md, the check-versions step's graphql branch (around lines 109-129) has two issues:

1. **Hard gate on auth_secret (line 112):** If auth_secret is missing or placeholder, the tool is added to unchanged_tools with "skipped -- no secret configured" and processing stops. This prevents public GraphQL APIs from being introspected. Fix: Remove this gate. Allow introspection to proceed regardless of whether auth is configured.

2. **Unconditional auth header in curl (lines 116-121):** The curl command always includes `-H "<auth_header>: <resolved_secret>"`. For public APIs with no auth configured, this sends a garbage header. Fix: Make the auth header conditional:
   - If auth_secret exists in the tool config AND is not a placeholder (not containing "REPLACE_WITH"): include the `-H "<auth_header>: <resolved_secret>"` flag.
   - Otherwise: omit the `-H` flag entirely — just send the introspection query without auth.

The resulting flow should be:
1. Read secrets.md if auth_secret is configured for this tool.
2. Build curl command: always include Content-Type and the introspection query body. Only add the auth header if a real (non-placeholder) secret was resolved.
3. Run curl with 15-second timeout.
4. On failure, skip gracefully (existing behavior).
5. On success, compare schema (existing behavior).

Run `npm run lint:fix` after changes.
  </action>
  <verify>
    <automated>grep -n "skipped.*no secret" workflows/relearn-tools.md; echo "---"; grep -c "auth_header.*auth_secret\|resolved_secret" workflows/relearn-tools.md</automated>
  </verify>
  <done>GraphQL tools without auth_secret are introspected (not skipped). The curl command conditionally includes the auth header only when a real secret is configured. Public GraphQL APIs are introspected successfully.</done>
</task>
