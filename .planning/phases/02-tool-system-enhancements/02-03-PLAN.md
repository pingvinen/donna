Modify `workflows/add-tool.md` to support all 4 tool types. The changes are:

**1. Update objective:**
Change from "Declare an external CLI tool" to "Declare an external tool (CLI, REST API, GraphQL API, or MCP server), verify its connectivity, learn its capabilities, and persist the result to tools.md."

**2. Add new step "ask-tool-type" AFTER "ask-tool-name" and BEFORE "verify-installation":**
```markdown
<step name="ask-tool-type">
Use AskUserQuestion:
```
What type of tool is <tool_name>?

1. CLI — runs shell commands (e.g., gh, jira, kubectl)
2. REST API — HTTP endpoints (e.g., GitHub API, Slack API)
3. GraphQL API — GraphQL endpoint (e.g., Linear, GitHub GraphQL)
4. MCP server — Claude Code MCP tool (e.g., linear, postgres)
```

Store the answer as `<tool_type>`: one of `cli`, `rest`, `graphql`, `mcp`.
</step>
```

**3. Make "ask-tool-name" step branch on type:**
For CLI: keep existing behavior (ask for CLI command, resolve to tool name).
For REST/GraphQL: instead of asking for CLI command, use AskUserQuestion:
```
Base URL for <tool_name>? (e.g., https://api.github.com)
```
Store as `<base_url>`. Set `<command>` to `<base_url>` (for display purposes).
For MCP: skip command question entirely. Set `<command>` to `mcp` (placeholder).

Actually, reorder: ask-tool-type should come AFTER ask-tool-name but its logic should gate the command question. So update ask-tool-name to only ask the CLI command question. Then in ask-tool-type, if type is rest or graphql, ask for base_url. If mcp, skip.

**4. Update "verify-installation" step:**
Add a conditional at the top: `If <tool_type> is not "cli", skip this step.`

**5. Update "auth-test" step to handle all types:**
For CLI: keep existing behavior (well-known auth tests for gh/jira/kubectl).
For REST/GraphQL: add API connectivity validation:
```markdown
If `<tool_type>` is "rest" or "graphql":

Use AskUserQuestion to ask for the auth header name and secret key name:
```
Auth header for <tool_name>? (e.g., Authorization, X-API-Key) Default: Authorization
```
Store as `<auth_header>` (default: `Authorization`).

```
Secret key name in secrets.md for <tool_name>? (e.g., GITHUB_TOKEN, SLACK_TOKEN)
```
Store as `<auth_secret>`.

**Set up secrets.md:**
Read `<storage_repo>/donna/secrets.md` with the Read tool. If the file does not exist, create it:
```markdown
---
# secrets.md -- managed by user, never by donna
# Auto-added to .gitignore
---
```

Check if `<auth_secret>` already exists in secrets.md. If not, append a placeholder line:
```
<auth_secret>: REPLACE_WITH_YOUR_SECRET
```

Write the updated secrets.md.

**Ensure secrets.md is gitignored:**
Read `<storage_repo>/.gitignore`. If it does not contain `donna/secrets.md`, append the line `donna/secrets.md` and write back. If `.gitignore` does not exist, create it with `donna/secrets.md`.

**Validate API connectivity:**
Read `<storage_repo>/donna/secrets.md` to get the current value for `<auth_secret>`. If the value is `REPLACE_WITH_YOUR_SECRET` or empty, print:
```
! No secret set for <auth_secret> — edit donna/secrets.md before testing connectivity.
```
Skip validation.

If a real secret value exists, run via Bash:
```bash
curl -s -o /dev/null -w "%{http_code}" -H "<auth_header>: <resolved_secret>" <base_url> 2>&1
```
- 200-299: print `! API reachable at <base_url>`
- 401/403: print `! Authentication failed — check <auth_secret> in donna/secrets.md`
- Other/timeout: print `! Could not reach <base_url>`
```

For MCP: print `MCP server auth is managed in Claude Code settings. Skipping auth test.`

**6. Update "ask-scope" step:**
For CLI: keep existing behavior.
For REST/GraphQL: adjust the prompt to be API-relevant: `What scope should Donna use for <tool_name>? (e.g., specific endpoints, resource filters). Leave blank for no filtering.`
For MCP: adjust prompt: `What scope should Donna use for <tool_name>? (e.g., specific resources to monitor). Leave blank for no filtering.`

**7. Update "learn-capabilities" step to handle all types:**
For CLI: keep existing behavior (well-known baselines + --help for unknown).
For REST: use AskUserQuestion:
```
Define capabilities for <tool_name>. Each capability is a name and HTTP method + path.
Format: <name>: <METHOD> /path?params

Examples:
- list-issues: GET /repos/{owner}/{repo}/issues?state=open
- my-profile: GET /user

Enter capabilities (one per line, blank line when done):
```
For GraphQL: use AskUserQuestion:
```
Define capabilities for <tool_name>. Each capability is a name and a GraphQL query (single line).
Format: <name>: query { ... }

Examples:
- my-issues: query { viewer { issues(first: 20, states: OPEN) { nodes { title url } } } }

Enter capabilities (one per line, blank line when done):
```
For MCP: use AskUserQuestion:
```
Define capabilities for <tool_name>. Each capability is a name and an MCP tool reference.
Format: <name>: mcp:<server_name>/<tool_name>

Examples:
- list-issues: mcp:linear/list_issues
- search-docs: mcp:notion/search

Enter capabilities (one per line, blank line when done):
```

**8. Update "write-tools-md" step for type-specific formats:**
For CLI tools, use the existing format but with the `type: cli` field (already added by Plan 01).
For REST tools:
```markdown

- type: rest
- base_url: <base_url>
- auth_header: <auth_header>
- auth_secret: <auth_secret>
- scope: <scope or "none">
- learned: <today's date YYYY-MM-DD>

### Capabilities
- <name>: <METHOD> /path
```
For GraphQL tools:
```markdown
## <tool_name>

- type: graphql
- base_url: <base_url>
- auth_header: <auth_header>
- auth_secret: <auth_secret>
- scope: <scope or "none">
- learned: <today's date YYYY-MM-DD>

### Capabilities
- <name>: <graphql_query>
```
For MCP tools:
```markdown
## <tool_name>

- type: mcp
- learned: <today's date YYYY-MM-DD>

### Capabilities
- <name>: mcp:<server>/<tool>
```

**9. Update "confirm" step:**
For REST/GraphQL: mention the secrets file:
```
! Added <tool_name> to tools registry (type: <tool_type>)
  Base URL: <base_url>
  Capabilities: <count> configured
  Secrets: Edit donna/secrets.md to set <auth_secret>

  Run /donna:begin-the-day to see tool data in your daily brief.
```
For MCP:
```
! Added <tool_name> to tools registry (type: mcp)
  Capabilities: <count> configured

  Ensure the MCP server is configured in Claude Code settings.
  Run /donna:begin-the-day to see tool data in your daily brief.
```

IMPORTANT: Donna NEVER prompts for actual secret values. The workflow only asks for the KEY NAME (e.g., `GITHUB_TOKEN`). The user must edit secrets.md directly to add the actual value. This is a locked security decision.
