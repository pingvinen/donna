Create `.claude/commands/gsd-custom/ingest-issues.md` -- a project-local slash command file.

FRONTMATTER (per D-14): The YAML frontmatter block must contain:
- `name: gsd-custom:ingest-issues`
- `description: Ingest open GitHub issues into GSD as TODOs with provenance tracking`
- `allowed-tools:` listing Read, Write, Bash, Glob, Grep, AskUserQuestion

OBJECTIVE SECTION: Batch-process all open GitHub issues on `pingvinen/donna` that lack both `ingested` and `not-for-ingestion` labels. For each: classify, check for duplicates against pending TODOs, create TODO file(s) with provenance, comment on the issue, and apply the appropriate label.

PROCESS STEPS (inline, NOT referencing external workflow files per gsd-custom pattern):

Step 1 `check-gh-auth`: Run `gh auth status` to verify CLI authentication. Fail fast if not authenticated.

Step 2 `ensure-labels` (per D-06): Run `gh label create "ingested" --description "Issue has been ingested into GSD" --color "1b157c" --repo pingvinen/donna 2>/dev/null || true` and `gh label create "not-for-ingestion" --description "Not suitable for GSD ingestion" --color "25b3f7" --repo pingvinen/donna 2>/dev/null || true`

Step 3 `list-issues` (per D-15): Run `gh issue list --repo pingvinen/donna --state open --json number,title,body,labels --limit 100`. Filter the JSON output to exclude issues that already have `ingested` or `not-for-ingestion` labels. If no issues remain, print "No new issues to ingest" and exit.

Step 4 `read-pending-todos` (per D-02): Read all files from `.planning/todos/pending/*.md` using Glob + Read. Collect title and content for semantic duplicate checking.

Step 5 `process-issues` (main loop): For each filtered issue:

5a. Read full issue: `gh issue view <number> --repo pingvinen/donna --json number,title,body,comments,labels`

5b. Classify: Analyze issue title and body to determine if it's a bug report, feature request, or neither.
- If neither (e.g., question, discussion, meta) -> apply `not-for-ingestion` label via `gh issue edit <number> --add-label "not-for-ingestion" --repo pingvinen/donna` -> skip to next issue
- If unclear -> use AskUserQuestion to ask the developer inline what to do (per D-01): "Issue #N: '<title>' -- Classify as: bug, feature, or skip (not-for-ingestion)?"

5c. Duplicate check (per D-02): Compare issue title and description against all pending TODO titles semantically. If a match is found, use AskUserQuestion: "Issue #N '<title>' looks similar to existing TODO '<todo_title>'. Skip, merge, or create anyway?"

5d. Create TODO(s) (per D-03, D-04): For each piece of work in the issue, write a TODO file using the Write tool to `.planning/todos/pending/<today-date>-<slugified-title>.md`. The TODO file must have YAML frontmatter with fields: `created` (ISO timestamp), `title` (descriptive title followed by ` (ref: #<issue_number>)`), `area` (inferred: general, tooling, etc.), `github_issue` (the issue number as integer), `files` (empty array `[]`). The body must have `## Problem` (summarized from issue title + body) and `## Solution` (from issue body if specified, otherwise "TBD").

5e. Comment on issue (per D-07): `gh issue comment <number> --repo pingvinen/donna --body "Ingested into GSD:\n- <TODO title 1>\n- <TODO title 2>"`

5f. Apply label (per D-05): `gh issue edit <number> --add-label "ingested" --repo pingvinen/donna` -- this MUST be the LAST step per issue (atomicity, see pitfall 2 in RESEARCH.md)

Step 6 `stage-and-summarize`: Stage new TODO files with `git add .planning/todos/pending/`. Print summary: "Ingested X issues into Y TODOs. Files staged -- run git commit to save." Do NOT run `git commit` (CLAUDE.md constraint, pitfall 7).

IMPORTANT CONSTRAINTS in the skill file:
- Hardcode `pingvinen/donna` as the repo (per CONTEXT.md specifics)
- Do NOT use `@~/.donna/workflows/` references -- all logic inline (gsd-custom pattern)
- Do NOT attempt git commits from the skill
- Apply `ingested` label as the LAST step for each issue (atomicity)
