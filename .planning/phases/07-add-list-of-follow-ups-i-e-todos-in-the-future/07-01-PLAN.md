  <action>
Create workflows/follow-up.md with the capture flow: init, parse-input, resolve-date, ensure-file, append-entry, git-commit, confirm -- 7 steps.

Step "init": Call node ~/.donna/donna-tools.cjs init via Bash (copy pattern from add-task.md verbatim -- parse JSON, handle not_configured error, extract storage_repo/daily_folder/auto_push, print update_available hint if non-null).

Step "parse-input": The argument is the full user text. Use language understanding to extract a task description and a time expression. If the argument contains a date/time phrase (in 2 months, on 2026-09-15, next Tuesday, in 3 weeks), isolate description and time expression. If no time expression, description is the full argument and due defaults to today. If no argument at all, use AskUserQuestion twice: first ask "What task would you like to schedule?", then ask "When is it due? (e.g. 'in 2 months', 'on 2026-09-15', or leave blank for today)" using free-text input, not a picker. Store description and the time expression (or null) as due_expression.

Step "resolve-date": Three cases. Case 1: due_expression is null -- use today's date. Case 2: due_expression matches YYYY-MM-DD format -- use directly. Case 3: relative expression -- the agent parses natural language into {value, unit} pairs (e.g. "in 2 months" = months:2, "in 3 weeks and 2 days" = weeks:3 + days:2), then injects arithmetic into a Bash node -e command. Command template: const d = new Date(); apply setMonth first (d.setMonth(d.getMonth() + N)), then setDate (d.setDate(d.getDate() + N)), then setFullYear (d.setFullYear(d.getFullYear() + N)). Extract local components: getFullYear(), getMonth() + 1 padded to 2 chars, getDate() padded to 2 chars. Output YYYY-MM-DD. NEVER use toISOString(). If the resolved date is NaN or invalid, fall back to today's date (per T-07-01 mitigation). Store resolved date as due_date.

Step "ensure-file": Check if storage_repo/donna/follow-ups.md exists. If not, create it with Write tool using frontmatter: created: today (YYYY-MM-DD), followed by ## Follow-ups heading. No other frontmatter fields.

Step "append-entry": Read storage_repo/donna/follow-ups.md with Read tool. Append line: - [ ] description | due: due_date (per D-02 format). Write back with Write tool.

Step "git-commit": Run via Bash: node ~/.donna/donna-tools.cjs commit "donna(follow-up): description" --files donna/follow-ups.md

Step "confirm": Print: checkmark Follow-up scheduled: description (due: due_date)
  </action>
