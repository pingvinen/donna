  <action>
Insert a new step name="check-follow-ups" in workflows/begin-the-day.md between the existing check-recurring step and pull-tool-data step. The new step:

Read storage_repo/donna/follow-ups.md with the Read tool. If the file does not exist, set follow_up_tasks to an empty list and continue (follow-ups are optional).

Parse each line matching the pattern: - [ ] description | due: YYYY-MM-DD. For each entry:
- Parse the due date (YYYYY-MM-DD)
- If due is before today: task is past due. Add to follow_up_tasks as: - [ ] description (overdue N days) where N = days between due and today.
- If due equals today: task is due today. Add to follow_up_tasks as: - [ ] description (no annotation).
- If due is after today: task is future -- leave in follow-ups.md, do not add to follow_up_tasks.

Past-due date calculation uses macOS-compatible date arithmetic (matching the existing check-recurring approach):

```bash
DUE="YYYY-MM-DD"
TODAY="YYYY-MM-DD"
due_epoch=$(date -j -f "%Y-%m-%d" "$DUE" "+%s")
today_epoch=$(date -j -f "%Y-%m-%d" "$TODAY" "+%s")
echo $(( (today_epoch - due_epoch) / 86400 ))
```

After collecting all due/overdue tasks, remove those lines from follow-ups.md (the matched lines are NOT written back -- only future lines remain). If lines were removed, write the updated file back with the Write tool. If no lines were removed, skip the file write. Per D-03: items are removed, not checked off or left with a marker.

Store follow_up_tasks for use in the deduplicate step.

CRITICAL constraints:
- The step reads only one specific named file (donna/follow-ups.md) -- no glob, no ls
- File existence check is done via Read tool (handle missing file gracefully)
- macOS date command uses the exact same pattern as existing check-recurring step
