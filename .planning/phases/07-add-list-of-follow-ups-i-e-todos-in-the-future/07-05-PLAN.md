Remove the overdue annotation from the begin-the-day workflow. This plan: removes the overdue days calculation, merges past-due into the due-today branch, cleans up dedup normalization, updates the print-brief example, and flips the test assertion.

Purpose: Eliminate an unnecessary annotation that creates maintenance complexity when tasks carry forward.
Output: A simplified check-follow-ups step (single `due <= today` branch), cleaned-up dedup normalization, updated print-brief example, and flipped test assertion.
</objective>

**1. In check-follow-ups step (lines 97-124):**
Remove the overdue days calculation block (lines 103-111 — the `if due < today` branch with `date -j` arithmetic). Merge past-due and due-today into a single condition: any entry where `due <= today` gets surfaced without annotation.

Replace the three-branch logic (lines 102-113) with:
```
- Parse the `due` date (YYYY-MM-DD).
- If `due <= <today>`: add to `<follow_up_tasks>` as: `- [ ] <description>` (no annotation).
- If `due > <today>`: task is future — leave the line in follow-ups.md. Do not add to `<follow_up_tasks>`.
```

Per the existing research finding: "As long as it hits my task list, I am fine" — the overdue annotation is unnecessary complexity. All due/past-due tasks surface identically as `- [ ] <description>`.

**2. In deduplicate step (line 244):**
Remove the sentence about `(overdue N days)` suffix stripping. The current text:
```
The `(overdue N days)` suffix is stripped during normalization (same as `(N times)`), so an overdue follow-up `- [ ] Review design doc (overdue 3 days)` does not duplicate a manually-added `- [ ] Review design doc`.
```

Replace with nothing (delete the sentence). The dedup normalization at line 236 already covers `(N times)` — no overdue suffix exists to strip, so no mention is needed.

Also update the normalization rule at line 236: remove `strip any trailing (overdue N days) suffix (where N is any integer)` from the list of normalization operations. That clause no longer applies.

**3. In print-brief step (line 339):**
Change the example from:
```
- [ ] Submit expense report (overdue 3 days)
```
to:
```
- [ ] Submit expense report
```
The overdue annotation no longer exists in the data — the print-brief example should reflect plain task descriptions.
