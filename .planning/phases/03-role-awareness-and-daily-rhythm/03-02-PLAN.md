**Workflow** (`workflows/begin-the-day.md`):
Create a workflow file titled "# Donna Begin-the-Day Workflow" with these steps:

1. `<step name="read-config">` — Read `~/.config/donna/config.md`. If missing, print error and stop. Extract `storage_repo`, `daily_folder` (default: `daily`), `auto_push`. Same pattern as add-task.md. Include the Obsidian sync check (same as add-task.md).

2. `<step name="get-today">` — Run `date +%Y-%m-%d` via Bash. Store as `<today>`. Also get day-of-week: `date +%A` (e.g., "Monday"). Also get day-of-month: `date +%-d`. Construct daily file path: `<storage_repo>/<daily_folder>/<today>.md`.

3. `<step name="find-previous-file">` — Find the most recent previous daily file. Run via Bash:
```bash
TODAY=$(date +%Y-%m-%d)
DAILY_DIR="<storage_repo>/<daily_folder>"
PREV_FILE=$(ls "$DAILY_DIR"/*.md 2>/dev/null | sort | grep -v "$TODAY" | tail -1)
echo "${PREV_FILE:-NONE}"
```
CRITICAL: The `grep -v "$TODAY"` exclusion prevents the self-referencing loop described in Pitfall 2 (RESEARCH.md). If result is "NONE", there is no previous file — skip carry-forward. This reads a directory listing only (satisfies STORE-03), then reads at most ONE previous file.

4. `<step name="carry-forward">` — If a previous file was found, read it with the Read tool. Extract all open tasks (`- [ ] ...` lines). For each open task:
   - If the description ends with ` (N times)`: extract N, increment to N+1, replace suffix with ` (N+1 times)`
   - If no counter suffix: append ` (1 times)`
   Store the resulting list as `<carried_tasks>`. Do NOT modify the previous file (historical record preserved per locked decision).

5. `<step name="check-recurring">` — Read `<storage_repo>/recurring.md` with the Read tool. If the file does not exist, skip this step (recurring tasks are optional — set-role may not have been run yet). Parse each line matching `- <description>: <interval>`. For "every other" intervals, also parse the `| last_run: YYYY-MM-DD` suffix.

   For each task, determine if it is due today using this logic:
   - `every <DayName>` (e.g., "every Monday"): due if today's day-of-week matches DayName
   - `every weekday`: due if today is Monday through Friday
   - `first <DayName> of month`: due if today's day-of-week matches AND day-of-month <= 7
   - `every other <DayName>` with `| last_run: YYYY-MM-DD`: due if today's day-of-week matches AND days since last_run >= 14. Use macOS-compatible date arithmetic:
     ```bash
     last_run_epoch=$(date -j -f "%Y-%m-%d" "$LAST_RUN" "+%s")
     today_epoch=$(date +%s)
     days=$(( (today_epoch - last_run_epoch) / 86400 ))
     ```
   Store due tasks as `<recurring_tasks>` (just the description, without the interval).

6. `<step name="read-existing-today">` — If today's daily file already exists, read it. Extract all task lines (both `- [ ]` and `- [x]`). Store as `<existing_tasks>`. If the file doesn't exist, `<existing_tasks>` is empty.

7. `<step name="deduplicate">` — Assemble the full task list and deduplicate in a single pass (per locked decision on idempotency):
   - Start with `<existing_tasks>` (both open and closed — they take priority)
   - Add `<carried_tasks>` — but only if no existing task matches after normalization
   - Add `<recurring_tasks>` as `- [ ] <description>` — but only if no existing task matches after normalization

   Normalization for comparison: strip `- [ ] ` or `- [x] ` prefix, strip ` (N times)` suffix, lowercase, trim whitespace.

   CRITICAL (Pitfall 6 from RESEARCH.md): A closed task `- [x] Review PRs` must block a recurring `- [ ] Review PRs` from being re-added. Both open AND closed existing tasks prevent duplicates.

   CRITICAL (Pitfall 3 from RESEARCH.md): If a carried-forward task already exists in today's file (from a previous run), do not re-add it or re-increment its counter.

8. `<step name="write-daily-file">` — Ensure the daily folder exists (`mkdir -p`). Write today's daily file with:
   - YAML frontmatter: `date: <today>`
   - `## Tasks` heading
   - All deduplicated tasks, grouped: existing tasks first (preserving order and state), then carried-forward tasks, then recurring tasks

9. `<step name="update-recurring-last-run">` — If any "every other" recurring tasks were added today, update their `last_run` date in `recurring.md`. Read the full file, update the relevant line(s) with `| last_run: <today>`, write the full file back (same read-modify-write pattern as done.md's mark-complete step).

10. `<step name="git-commit">` — Same pattern as add-task.md: `git -C <storage_repo> add -A`, check porcelain, commit with message `donna(begin-the-day): daily brief for <today>`. Push if auto_push is true.

11. `<step name="print-brief">` — Print the daily brief to the terminal. Use the banner from `src/output.cjs` pattern. Action-first layout (per locked decision):
    ```
    ══════════════════════════════════════
     DONNA — Daily Brief for <today>
    ══════════════════════════════════════

    ## Carried Forward
    - [ ] Follow up with Sarah (3 times)
    - [ ] Review design doc (1 times)

    ## Due Today
    - [ ] Check team Slack
    - [ ] Review sprint backlog

    ══════════════════════════════════════
    ```
    Show ALL tasks, never truncate (per locked decision). If no carried-forward tasks, omit that section. If no recurring tasks due, omit that section. If both empty and no existing tasks, print "No tasks for today — enjoy your day!"
