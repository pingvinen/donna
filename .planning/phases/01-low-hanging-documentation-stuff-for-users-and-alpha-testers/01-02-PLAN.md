**workflows/help.md** — Create the conversational troubleshooting workflow with these steps:

1. **`banner`** — Print `━━━ Donna ▸ Help ━━━`

2. **`read-config`** — Read `~/.config/donna/config.md`. If missing, print `✗ Donna is not configured. Run /donna:setup first.` and stop. Extract `storage_repo`, `daily_folder` (default: `daily`), `auto_push` (default: false).

3. **`ask-problem`** — Use AskUserQuestion:
   ```
   What do you need help with?

   Some things I can help diagnose:
   - Configuration issues
   - Storage repo problems
   - Skills not working
   - Tool integration issues
   - General questions about how Donna works

   Describe what's going on:
   ```

4. **`diagnose`** — Based on the user's response, inspect relevant state. Use keyword matching to determine the category and run the appropriate checks:

   **Config issues** (keywords: config, setup, configure, path):
   - Read `~/.config/donna/config.md` and display its contents
   - Check if `storage_repo` path exists: `test -d <storage_repo> && echo "EXISTS" || echo "MISSING"`
   - Check if storage_repo is a git repo: `git -C <storage_repo> status 2>&1 | head -1`

   **Storage issues** (keywords: storage, repo, git, daily, file, missing):
   - Check storage_repo exists and is git repo (same as above)
   - Check for donna/ subfolder: `ls <storage_repo>/donna/ 2>/dev/null`
   - Check for daily folder: `ls <storage_repo>/<daily_folder>/ 2>/dev/null | tail -5`
   - Check for uncommitted changes: `git -C <storage_repo> status --short 2>/dev/null`

   **Skill issues** (keywords: skill, command, slash, workflow, not working, error):
   - Check stubs installed: `ls ~/.claude/commands/donna/ 2>/dev/null`
   - Check workflows installed: `ls ~/.donna/workflows/ 2>/dev/null`
   - Compare stub count vs workflow count
   - Check Donna version: read `~/.donna/version.md`

   **Tool issues** (keywords: tool, gh, jira, integration, pull, refresh):
   - Read `<storage_repo>/donna/tools.md` if it exists
   - For each tool found, check if installed: `which <tool_name> 2>/dev/null`
   - Check gh auth if gh is a configured tool: `gh auth status 2>&1`

   **General / no clear category:**
   - Run all checks from above and present a full health summary
   - Print Donna version, config status, storage status, installed skills count, configured tools

   After running diagnostics, present findings clearly:
   - Use `✓` for things that look good
   - Use `✗` for things that look broken
   - Provide specific fix suggestions for each `✗` item

5. **`follow-up`** — Use AskUserQuestion:
   ```
   Did that help? You can:
   1. Ask about something else
   2. Submit a bug report or feature idea (I'll point you to /donna:contribute-idea)
   3. Done — I'm all set

   What would you like to do?
   ```

   - If 1: loop back to diagnose step with new question
   - If 2: print `Tip: Run /donna:contribute-idea to submit ideas or bug reports via GitHub Issues.` and stop
   - If 3: print `✓ Glad I could help!` and stop

**workflows/contribute-idea.md** — Create the idea submission workflow with these steps:

1. **`banner`** — Print `━━━ Donna ▸ Contribute Idea ━━━`

2. **`check-gh-auth`** — Run `gh auth status 2>&1` via Bash. If exit code is non-zero, print:
   ```
   ✗ The gh CLI is not authenticated. Run 'gh auth login' first, then re-run /donna:contribute-idea.
   ```
   Stop.

3. **`ask-idea`** — Use AskUserQuestion:
   ```
   What's your idea or bug report?

   Describe it in a few sentences — I'll check if something similar already exists before creating an issue.
   ```
   Store the response as `<user_idea>`.

4. **`check-duplicates`** — Check two sources for potential duplicates:

   **Source 1: GitHub Issues**
   Run via Bash:
   ```bash
   gh issue list --repo pingvinen/donna --state open --json number,title,url --limit 100
   ```
   Parse the JSON output. Compare each issue title against `<user_idea>` using semantic similarity (Claude judges whether the idea overlaps with an existing issue — do not use brittle substring matching).

   **Source 2: GSD pending todos from STATE.md on GitHub**
   Run via Bash:
   ```bash
   gh api repos/pingvinen/donna/contents/.planning/STATE.md --jq '.content | @base64d'
   ```
   Parse the `### Pending Todos` section from the decoded content. Each bullet is a pending todo. Compare each todo against `<user_idea>` using semantic similarity.

   If either source has a potential match, present the match(es) to the user:
   ```
   I found something similar:

   [For GitHub Issue match:]
   → Issue #<number>: <title>
     <url>
     You can upvote or comment on this issue instead of creating a new one.

   [For pending todo match:]
   → Pending todo: "<todo text>"
     This is already tracked internally.
   ```

   Then use AskUserQuestion:
   ```
   Would you like to:
   1. Create a new issue anyway (it's different enough)
   2. Skip — the existing one covers my idea
   ```
   If skip, print `✓ Thanks for checking! The existing item covers this.` and stop.

   If no duplicates found, proceed to create-issue step.

5. **`create-issue`** — Help the user create a well-formed GitHub Issue:

   Use AskUserQuestion:
   ```
   Let me help you write up the issue. Here's what I've drafted based on your idea:

   Title: <suggested title based on user_idea>

   Body:
   <suggested body with description, context, and expected behavior>

   Would you like to:
   1. Submit as-is
   2. Edit the title or body first
   3. Cancel
   ```

   If edit: use AskUserQuestion to get edits, then re-present.
   If cancel: print `Issue cancelled.` and stop.
   If submit: run via Bash:
   ```bash
   gh issue create --repo pingvinen/donna --title "<title>" --body "<body>"
   ```
   Print the resulting issue URL with a success message:
   ```
   ✓ Issue created: <url>
   ```
