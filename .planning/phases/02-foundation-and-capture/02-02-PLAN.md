(No AskUserQuestion — add-task takes inline arg; if missing, Claude can prompt naturally without needing explicit tool permission since it can just read the instruction to ask.)

    Actually — per RESEARCH.md Pattern 2 and CONTEXT.md locked decision, if no argument is provided the workflow should prompt the user. Include AskUserQuestion in allowed-tools to be safe for the prompting case.

    Reference: `@~/.donna/workflows/add-task.md`

    **Create `workflows/add-task.md`:**
    Steps:
    1. **read-config**: Read `~/.config/donna/config.md`. If missing, print `✗ Donna is not configured. Run /donna:setup first.` and stop. Extract `storage_repo` path.
    2. **get-description**: The task description is provided as the argument to this command (e.g., `/donna:add-task buy milk`). If no argument was provided, use AskUserQuestion to ask "What task would you like to add?"
    3. **ensure-daily-file**: Run `date +%Y-%m-%d` to get today's date. Construct path `<storage_repo>/daily/<date>.md`. Run `mkdir -p <storage_repo>/daily`. If the daily file does not exist, create it with:
       ```
       ---
       date: <YYYY-MM-DD>
       ---

       ## Tasks
       ```
    4. **append-task**: Read the daily file. Append `- [ ] <description>` on a new line after the last line in the file (or after the `## Tasks` heading if the file was just created). Write the updated file.
    5. **git-commit**: Run `git -C <storage_repo> add -A`. Check `git -C <storage_repo> status --porcelain` — if empty, skip commit. Otherwise run `git -C <storage_repo> commit -m "donna(add-task): <description>"`. If `auto_push` is true in config, run `git -C <storage_repo> push`.
    6. **confirm**: Print `✓ Added: <description>` and the path to the daily file.

    **Create `stubs/claude-code/donna/done.md`:**
    Follow stub template. Name: `donna:done`. Description: "Mark tasks as complete in today's daily journal". Allowed-tools: Read, Write, Bash, AskUserQuestion.
    Reference: `@~/.donna/workflows/done.md`

    **Create `workflows/done.md`:**
    Steps:
    1. **read-config**: Same pattern as add-task — read config, extract storage_repo, fail if missing.
    2. **find-daily-file**: Run `date +%Y-%m-%d` to get today's date. Construct path `<storage_repo>/daily/<date>.md`. If the file does not exist, print `✗ No daily file for today. Add a task first with /donna:add-task` and stop.
    3. **read-tasks**: Read the daily file. Find all lines matching `- [ ] <description>` (open tasks). If no open tasks found, print `✓ All tasks already complete for today!` and stop.
    4. **select-tasks**: Two modes based on whether an argument was provided:
       - **With argument** (e.g., `/donna:done buy milk`): Fuzzy-match the argument against open task descriptions using Claude's natural language understanding. If a match is found, show it and use AskUserQuestion to confirm: "Mark as done: '<task>'? (yes/no)". If no match, tell the user and list open tasks.
       - **Without argument**: Show a numbered list of all open tasks. Use AskUserQuestion to ask which task(s) to mark as done (user can enter numbers, comma-separated for multiple).
    5. **mark-complete**: For each confirmed task, replace `- [ ] <description>` with `- [x] <description>` in the daily file. Write the updated file.
    6. **git-commit**: Same pattern as add-task — `git -C <storage_repo> add -A`, check status, commit with `donna(done): <description>` (or `donna(done): N tasks completed` if multiple), push if auto_push.
    7. **confirm**: Print `✓ Done: <description>` for each completed task.
