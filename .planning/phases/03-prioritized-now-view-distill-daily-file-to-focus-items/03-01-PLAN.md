  <action>
Create `workflows/focus.md` with the following structure. This is the core workflow file: a self-contained prompt that Claude Code executes when the user runs `/donna:focus`.

**Top-level structure:**
Start with `# Donna Focus Workflow`, then an `<objective>` block explaining: read today's daily file, score open tasks on urgency and context signals, optionally re-query active tools for enriched data, and produce a short prioritized focus list written to daily/focus.md and printed to the terminal. This is a read-only operation relative to the daily file: only focus.md is written.

**Step 1: `read-config`** Copy character-for-character from `run-tools.md` step `read-config` (identical across all workflows). Extracts `storage_repo`, `daily_folder` (default: `daily`), `auto_push` (default: false). Includes Obsidian sync logic.

**Step 2: `check-pending-migrations`** Copy character-for-character from `run-tools.md` step `check-pending-migrations`. Must include both `move-standing-files` and `backfill-tool-type` migration handlers. This step is identical in all workflows.

**Step 3: `read-daily-file`** Read today's daily file at `<storage_repo>/<daily_folder>/YYYY-MM-DD.md` where YYYY-MM-DD is today's date. If the file does not exist, print `No daily file for today. Run /donna:begin-the-day first.` and stop.

**Step 4: `parse-open-tasks`** Extract all lines matching `- [ ] ` (open tasks only, per D-12). Store as `<open_tasks>` list. Count total open items for the footer (D-18). For each open task line, parse:
- Tool tag: leading `(<tool_tag>) ` if present (regex `\(\w+\) ` after `- [ ] `)
- Carry-forward count: trailing ` (N times)` suffix where N is integer >= 1
- URL/identifier: trailing ` [<text>](<url>)` pattern
- Description text: everything between tool tag and trailing suffixes

**Step 5: `enrich-from-tools`** Per D-13, D-14, D-15, D-16:
1. Collect unique tool tags from `<open_tasks>` (e.g., `gh`, `jira`)
2. Read `<storage_repo>/donna/tools.md` to find matching `## <tool_name>` sections (tool_name matches the tag)
3. For each matched tool, extract its `type` field (default `cli`) and capabilities
4. Execute capabilities using the same type-aware execution logic from `run-tools.md` step `pull-fresh-data`:
   - If only one tool: execute directly
   - If multiple tools: spawn Task agents in parallel (same pattern as run-tools), with explicit instruction "DO NOT run git commands" in agent instructions
   - cli: `timeout 10 <cli_invocation> 2>&1`
   - rest: `timeout 10 curl -s -H "<auth_header>: <secret>" "<base_url><path>" 2>&1`
   - graphql: `timeout 10 curl -s -X POST -H "Content-Type: application/json" -H "<auth_header>: <secret>" -d '<query>' "<base_url>" 2>&1`
   - mcp: invoke MCP tool directly
   - Secrets resolution: read `<storage_repo>/donna/secrets.md`, resolve `$SECRET_NAME` references
5. On any tool failure: log warning, continue with text-only signals for that tool's items (D-15 graceful fallback)
6. Store enriched data as `<enriched_data>` keyed by tool tag

**Step 6: `score-and-rank`** Apply priority signals to each open task (per D-08 through D-12):

Text-analysis signals:
- Urgency keywords (D-08): Scan description (case-insensitive) for: "due today", "due tomorrow", "blocking", "urgent", "ASAP": strong positive signal
- Carry-forward count (D-09): Items with `(N times)` where N >= 5 are chronically neglected: elevated priority. N >= 1 means carried at least once.
- Recency/freshness (D-11): Items WITHOUT `(N times)` suffix are new today: mild positive signal
- Open state (D-12): Already filtered in parse step: only open items reach scoring

Tool enrichment signals (D-14):
- PR with review-requested status: elevated priority
- PR with changes-requested: elevated priority
- Jira item in "In Progress": moderate signal
- Any status indicating action needed from user: elevated

Claude selects 3-8 items dynamically based on urgency distribution (D-17). On a quiet day with few urgent items, show fewer. On a busy day with many urgent items, show more.

Produce `<focus_items>` as an ordered list.

**Step 7: `write-focus-file`** Write to `<storage_repo>/<daily_folder>/focus.md` (D-04, D-06, D-07):

The file must have YAML frontmatter with `date` (YYYY-MM-DD) and `generated` (HH:MM) fields, then a `## Focus (YYYY-MM-DD, HH:MM)` heading, numbered focus items each with a reason tag (e.g., "due today", "review requested", "urgent", "carried 8 times", "new today"), then a horizontal rule, then `<N> other items in today's file` where N = total open items minus focus items count (D-18). File is overwritten entirely each run (D-06).

**Step 8: `git-commit`** Follow exact pattern from `run-tools.md`:
Run `git -C <storage_repo> add -A` then `git -C <storage_repo> status --porcelain`. If output is not empty, run `git -C <storage_repo> commit -m "donna(focus): focus list for <YYYY-MM-DD>"`. If `auto_push` is true, run `git -C <storage_repo> push`.

**Step 9: `print-focus`** Print to terminal with banner (D-05), following begin-the-day pattern. Use the double-line box characters matching the banner in begin-the-day.md print-brief step. Show "Donna -- Focus for YYYY-MM-DD" in the banner, then the numbered focus items with reason tags, then the "N other items" footer, then the closing banner line.

**Critical constraints for the workflow:**
- NEVER modify the daily file (YYYY-MM-DD.md): this skill is read-only relative to daily files
- Only focus.md is written as output
- Task agents spawned for tool enrichment must NOT run git commands (SSH signing constraint from CLAUDE.md)
- The read-config and check-pending-migrations steps must be copied character-for-character from run-tools.md
