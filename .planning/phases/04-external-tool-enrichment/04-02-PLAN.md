**Workflow: `workflows/relearn-tools.md`**

Steps:
1. **read-config** — Character-for-character identical to begin-the-day.md's read-config step.

2. **check-pending-migrations** — Character-for-character identical to begin-the-day.md's check-pending-migrations step.

3. **read-tools-md** — Read `<storage_repo>/donna/tools.md` with the Read tool. If the file does not exist, print `✗ No tools registered. Run /donna:add-tool first.` and stop. Parse each tool section: extract `command`, `version` (stored), `learned` date, and capabilities list.

4. **check-versions** — For each tool in tools.md, run via Bash:
```bash
<command> --version 2>/dev/null | head -1
```
Compare the output against the stored `version` field. Comparison is a simple string equality check (not semver parsing — "is it different?" is sufficient per research). Collect tools into two lists: `<changed_tools>` (version differs) and `<unchanged_tools>` (version matches). If `<command>` is not found (which fails), add to `<changed_tools>` with a warning.

5. **report-unchanged** — For each tool in `<unchanged_tools>`, print:
```
⊘ <tool_name>: unchanged at <version> — skipped
```
If ALL tools are unchanged, print `✓ All tools up to date. Nothing to re-learn.` and stop.

6. **relearn-changed** — For each tool in `<changed_tools>`, apply the same learn-capabilities logic as add-tool.md's learn-capabilities step:
- Well-known tools (gh, jira, kubectl): synthesize from training data
- Unknown tools: parse `<command> --help 2>&1 | head -80`
Do NOT ask the user to re-select capabilities — keep the same capability names, update only the CLI invocations if the training data suggests changes. Print:
```
✓ Re-learned <tool_name> (was <old_version>, now <new_version>)
```

7. **write-tools-md** — Update `<storage_repo>/donna/tools.md`: for each re-learned tool, update its `version`, `learned` date, and capabilities section. Upsert — do not remove other tool sections. Write with Write tool.

8. **git-commit** — Same pattern:
```bash
git -C <storage_repo> add -A
git -C <storage_repo> status --porcelain
```
If not empty:
```bash
git -C <storage_repo> commit -m "donna(relearn-tools): updated <count> tool(s)"
```
If auto_push, push.

9. **confirm** — Print summary:
```
✓ Re-learned <count> tool(s): <tool_names>
  <count> tool(s) unchanged: <tool_names>
```

**Workflow: `workflows/refresh-tools.md`**

Steps:
1. **read-config** — Character-for-character identical to begin-the-day.md's read-config step.

2. **check-pending-migrations** — Character-for-character identical to begin-the-day.md's check-pending-migrations step.

3. **read-tools-md** — Read `<storage_repo>/donna/tools.md`. If file does not exist, print `✗ No tools registered. Run /donna:add-tool first.` and stop. Parse tool sections and capabilities.

4. **find-daily-file** — Get today's date via Bash: `date +%Y-%m-%d`. Store as `<today>`. Construct path: `<storage_repo>/<daily_folder>/<today>.md`. If the file does not exist, print `✗ No daily file for today. Run /donna:begin-the-day first.` and stop.

5. **read-existing-tool-tasks** — Read today's daily file. Extract all lines from `## From Tools` section and `## Resolved` section. For each line, extract the embedded URL from `[tool](url)` pattern — this URL is the stable identifier for matching. Store as `<existing_tool_lines>` (map of URL -> full line, including checkbox state).

6. **pull-fresh-data** — For each tool in tools.md, for each capability:
Run the capability command via Bash with a 10-second timeout:
```bash
timeout 10 <capability_command> 2>&1
```
On success (exit 0): Parse the output into task entries. Each entry gets format: `- [ ] <description> [<tool_name>](<url>)`. For gh JSON output, extract `number`, `title`, `url` fields. For jira plain output, extract issue key and summary.
On failure (exit non-zero, including exit 124 for timeout): Add warning: `! <tool_name>: <error_description>`. Continue to next tool. Never retry.

Store fresh tasks as `<fresh_tool_tasks>` (map of URL -> task line).

7. **smart-merge** — Apply three-way merge rules in priority order. Read-modify-write the ENTIRE daily file atomically:

For each URL in `<existing_tool_lines>`:
  - If line is `[x]` (user manually checked): **KEEP AS-IS** (user intent wins, rule 1). Do not change regardless of tool state.
  - If line is `[ ]` AND URL exists in `<fresh_tool_tasks>`: **KEEP OPEN** (still active).
  - If line is `[ ]` AND URL is NOT in `<fresh_tool_tasks>`: the item was removed from the tool (reassigned, deleted, or closed). Check if the tool reported it as closed/merged (for gh: check PR/issue state via `gh pr view <number> --json state` or similar). If closed/merged: change to `- [x] <description> [<tool>](<url>) (<reason>)` and move to `## Resolved`. If removed without status info: move to `## Resolved` with `(removed)`.

For each URL in `<fresh_tool_tasks>` that is NOT in `<existing_tool_lines>`:
  - **ADD** to `## From Tools` section (new item, rule 4).

Collect all warning messages as `<tool_warnings>`.

Write the updated daily file with the Write tool.

CRITICAL: This is a read-modify-write operation. The entire file must be rewritten with all sections updated. Do NOT just append — remove items from `## From Tools` when moving them to `## Resolved`.

8. **git-commit** — Same pattern:
```bash
git -C <storage_repo> add -A
git -C <storage_repo> status --porcelain
```
If not empty:
```bash
git -C <storage_repo> commit -m "donna(refresh-tools): refreshed tool data for <today>"
```
If auto_push, push.

9. **print-summary** — Print:
```
══════════════════════════════════════
 DONNA — Tool Refresh for <today>
══════════════════════════════════════
```
If new tasks were added: print each.
If tasks were auto-closed: print each with reason.
If tasks were moved to Resolved: print each with reason.
If there are warnings: print each warning line.
If nothing changed: print `No changes from tools.`
End with: `══════════════════════════════════════`
