Create following the exact pattern of `setup.md` stub. YAML frontmatter with:

- `description: Define your job role, research recurring tasks, and build your daily rhythm`
- `allowed-tools:` must include Read, Write, Bash, AskUserQuestion, AND WebSearch (WebSearch is critical — without it the research step will prompt for permission on every call, per Pitfall 1 in RESEARCH.md)

Objective block: "Run the Donna set-role workflow."
Execution context: `@~/.donna/workflows/set-role.md`

**Workflow** (`workflows/set-role.md`):
Create a workflow file titled "# Donna Set-Role Workflow" with these steps:

1. `<step name="read-config">` — Read `~/.config/donna/config.md`. If missing, print error and stop. Extract `storage_repo`, `auto_push`. Same pattern as add-task.md.

2. `<step name="check-existing-role">` — Run `test -f <storage_repo>/role.md` via Bash. If exists, proceed to re-run menu. If missing, proceed to ask-role step.

3. `<step name="rerun-menu">` — Use AskUserQuestion with 4 options:
   - "Something got messed up — start fresh (reset)"
   - "Got promoted or changed roles — update (diff-update)"
   - "Just want to refresh the research — re-research current role"
   - "Cancel"

   On "reset": proceed to ask-role (fresh start, will overwrite role.md and recurring.md).
   On "diff-update": read current role.md, proceed to ask-role but pre-fill with current values and note this is an update. After research, show delta (added/removed recurring tasks vs current recurring.md). Preserve any manually-added recurring tasks (tasks in recurring.md not in the research suggestions).
   On "re-research": skip to research step using existing role.md data.
   On "Cancel": print "Cancelled." and stop.

4. `<step name="ask-role">` — Stage 1: Use AskUserQuestion sequentially:
   - Ask job title
   - Ask about team size / direct reports
   - Ask about key responsibilities (2-3 things they focus on most)
   Store all answers.

5. `<step name="research">` — Stage 2: Use WebSearch to research the role. Construct targeted queries using ALL collected data from Stage 1 (per Pitfall 5 in RESEARCH.md — vague queries produce generic results). Run 2-3 focused searches:
   - "[job title] daily recurring tasks responsibilities"
   - "[job title] [key responsibilities] common tools workflows"

   Synthesize findings into a structured summary matching the role-research.md format (see interfaces above). Categorize recurring task suggestions by frequency (daily, weekly, monthly). List tool suggestions with brief descriptions.

6. `<step name="present-summary">` — Print a concise summary of research findings (2-3 sentences). Then use AskUserQuestion: "Which category would you like to review? (recurring tasks / tool suggestions / both / skip)"

7. `<step name="approve-recurring">` — If user chose to review recurring tasks: Display each category (daily, weekly, monthly) and use AskUserQuestion to let the user approve, reject, or modify each task. User can add notes like "make this biweekly" and Donna should interpret and adjust the interval. Collect the final approved list.

8. `<step name="approve-tools">` — If user chose to review tools: Display tool suggestions and note which ones are available. For approved tools, print: "Run `/donna:add-tool` to configure [tool name] (available in a future update)." Do NOT create tools.md or configure anything — just note them.

9. `<step name="save-role">` — Write `<storage_repo>/role.md` with YAML frontmatter (job_title, team_size, direct_reports, key_responsibilities array, updated date) and prose summary. Write `<storage_repo>/role-research.md` with YAML frontmatter (researched date, role) and full research findings.

10. `<step name="save-recurring">` — Write `<storage_repo>/recurring.md` with the approved recurring tasks. Format: one task per line as `- Task description: interval`. For "every other" intervals, append ` | last_run: <today>` suffix. YAML frontmatter comment only (no fields needed). If this is a diff-update, merge: keep manually-added tasks from old recurring.md, add new approved tasks, remove rejected tasks.

11. `<step name="git-commit">` — Same pattern as add-task.md: `git -C <storage_repo> add -A`, check porcelain, commit with message `donna(set-role): define role as <job_title>`. Push if auto_push is true.

12. `<step name="confirm">` — Print success: "✓ Role defined: [job title]", "✓ [N] recurring tasks saved to recurring.md", "✓ Research saved to role-research.md". If tools were noted, remind about /donna:add-tool.
