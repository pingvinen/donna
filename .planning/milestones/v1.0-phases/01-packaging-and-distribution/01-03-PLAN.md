<task type="auto" tdd="true">
  <name>Task 1: Version bump and changelog scripts with tests</name>
  <files>scripts/determine-bump.cjs, scripts/generate-changelog.cjs, test/determine-bump.test.cjs</files>
  <behavior>
    - Test (bump): "fix: something" commits produce "patch" bump
    - Test (bump): "feat: something" commits produce "minor" bump
    - Test (bump): "feat!: breaking" commits produce "minor" when version starts with 0. (pre-1.0 convention)
    - Test (bump): "BREAKING CHANGE" in commit message produces "minor" when version starts with 0.
    - Test (bump): mix of fix and feat commits produces "minor" (highest wins)
    - Test (bump): no conventional commits found exits with error
    - Test (bump): "chore:", "docs:", "ci:" commits produce "patch" bump
    - Test (bump): version calculation is correct (0.1.0 + minor = 0.2.0, 0.1.0 + patch = 0.1.1)
    - Test (changelog): groups commits by type (Features, Fixes, Other)
    - Test (changelog): outputs formatted markdown
  </behavior>
  <action>
    1. Create scripts/determine-bump.cjs following the RESEARCH.md code example. Key behaviors:
       - Gets last tag via `git describe --tags --abbrev=0`, falls back to initial commit if no tags
       - Reads commit messages since last tag via `git log`
       - Parses conventional commit prefixes (feat, fix, docs, chore, refactor, test, ci)
       - Determines bump: feat = minor, fix/chore/docs/etc = patch, breaking = major (but downgraded to minor for 0.x.y)
       - Calculates new version from current package.json version
       - Writes bump and new_version to GITHUB_OUTPUT (when running in CI) or prints to stdout (when testing)
       - Exits with code 1 if no commits found
    2. Create scripts/generate-changelog.cjs:
       - Reads commits since last tag (same approach as determine-bump)
       - Groups by type: "Features" (feat), "Fixes" (fix), "Other" (everything else)
       - Outputs markdown formatted changelog
       - Writes changelog to GITHUB_OUTPUT (when running in CI) or prints to stdout
    3. Make both scripts testable by extracting pure functions: `determineBump(messages, currentVersion)` returns `{ bump, newVersion }`, `generateChangelog(messages)` returns markdown string. Export these for testing while keeping the git-reading CLI behavior as the default when run directly.
    4. Write tests RED first, then GREEN. Tests call the exported pure functions with crafted commit message arrays -- no git dependency in tests.
  </action>
  <verify>
    <automated>node --test test/determine-bump.test.cjs</automated>
  </verify>
  <done>
    - determine-bump.cjs correctly identifies bump type from conventional commit messages
    - Pre-1.0 semver convention respected (breaking = minor, not major)
    - generate-changelog.cjs produces grouped markdown changelog
    - Both scripts work standalone (CLI) and as importable modules (testing)
    - All tests green
  </done>
</task>
